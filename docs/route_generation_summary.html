🗺️ WalkingWR – Route Generation (Detailed Summary)

Overview of how routes are generated, filtered, and displayed. Build 377+.

📍 Duration buckets & options

User selects one duration; the app aims for 2 in-band routes. “In-band” = duration within the acceptable band and distance ≥ minimum for that bucket.

SettingValue
Duration options[10, 15, 20, 25, 30] minutes (durationOptions)
Target in-band routes2 (targetInBandRoutes)
In-band band (duration)minMaxAcceptableMinutes(for:): rounded to nearest 5 min; 80–120% of rounded duration; 75–125% for edge buckets (rounded ≤5 or ≥55 min)
In-band min distanceminDistanceMetersForInBand: max(200, rounded × 50) m (≈50 m/min implied)
Minimum display %0.30 (minimumDisplayPercent). Route shown only if durationMinutes ≥ max(1, selectedDuration × 0.30); below that → “No routes found” + suggest other buckets

Wide band (pre-gen / +1): For short targets (rounded ≤10 min), isRouteInWideBand uses 65–125% so 7 min can be accepted for 10 min target; otherwise same 80–120%. Same min distance applies.

⏱️ High-level flow

1️⃣
Cache / pre-pop check – Session cache, then pre-populated DB. If hit, routes loaded; waypoints filtered (100 m under 25 min, 200 m for 25+ min; prepop always 200 m). Optionally re-measured with Google. In-band routes sorted first; if <2 in-band, pre-generation may still run.
2️⃣
Live generation – On cache miss (or severely short cached route), generateLocalRoute runs (MapKit / ORS / GraphHopper, then optional Google). Result filtered with filterCloseWaypointsSync (100 m / 200 m). First route checked for 30% minimum; if below → “No routes found”. Otherwise Route 1; optional Google re-measure for preview.
3️⃣
Second route (initial) – If allRoutes.count == 1: tryAddSecondRouteViaFreeEngines (up to 2 attempts, excluded first-route POIs); if still 1 and has API key, tryGooglePlacesFallbackToAddRoute with waypointOffset 0 then 1 (2–3 waypoints per attempt, in-band only).
4️⃣
Pre-generation – Background: up to maxPregenAttempts = 10, pregenTimeCap = 55 s. Excludes POIs/place IDs of existing routes; uses isRouteInWideBand for acceptance; stops on 2 in-band or time/attempt cap. maxConsecutiveFailures = 3, maxConsecutiveDuplicates = 3 (then varietyExhausted = true). Pauses while +1 is running. Prefer multi-waypoint only for 30+ min when 2–4 routes.
5️⃣
Google POI fallback – If still <2 routes, fetch more POIs from Google and generate more; in-band only; <50% stored in cross-bucket, not added.
6️⃣
Second-chance – One more tryAddSecondRouteViaFreeEngines; then tryGooglePlacesFallbackToAddRoute with waypointOffset 2, 3. secondChanceTimeCap = 15 s.
7️⃣
Cross-bucket safety net – Pull from session cross-bucket pool: duration in 50–150% of selected; sort in-band (80–120%) first, then by closeness to target. Last resort: add best rejected short route only if duration ≥30% of selected.
8️⃣
Google re-measure sweep – Re-measure any route not yet Google-measured. Prune fallbacks outside 50–150% if we have >1 route.
📱 App: “Choose a Route” → duration chips (10–30 min) → Generate → loading stages → map preview with route cards (1 of 2, 2 of 2).

🔄 First route (live)

  • POI fetch – Apple / OSM / Geograph, then optional Google. Pre-fetched POIs used for on-route enrichment when route has ≤2 waypoints.
  • generateLocalRoute – MapKit / ORS / GraphHopper; optional 30 s Google fallback loop for in-band. Result passed through filterCloseWaypointsSync: waypoints within 100 m (under 25 min) or 200 m (25+ min) of each other collapsed to avoid clustered village waypoints.
  • 30% gate – isRouteBelowMinimumDisplay(routeMinutes, selectedDuration): routeMinutes < max(1, selectedDuration × 0.30). If first route fails: allRoutes = [], generatedRoute = nil, showMapPreview = true, errorMessage = "No routes found for X min. Try A, B, C min instead." (other durations from durationOptions). UI: “No routes found” + “Choose another duration”.
  • If 30–50%: shown as route 1, marked short/fallback; stored in cross-bucket.
  • If ≥50% and in-band: shown normally. Gemini naming when in-band; template kept for out-of-band. Optional road-snap race (ORS vs Google, 15 s cap) for polyline.

➕ Second route (initial – free engines then Google)

When allRoutes.count == 1 after first route is set:

  1. Free engines – tryAddSecondRouteViaFreeEngines (up to 2 attempts). Excludes first-route POIs via excludePlaceIds / excludePOIs. generateLocalRoute; if result is in-band (isRouteInBand) and unique (signature + primary POI), build WalkingRoute (markers, directions, template name), appendRouteIfAllowed, then lazy Gemini Task replaces template name/description.
  2. Google Places fallback – If still 1 route and mapsService.hasAPIKey: tryGooglePlacesFallbackToAddRoute(userCoordinate, source: "initial_one_route_fallback", waypointOffset: 0), then waypointOffset: 1 on retry. Uses fetchGooglePOIsOnDemand (excludes existing route places); slice of 2–3 waypoints (maxWaypoints = 3, start = min(waypointOffset*2, googlePOIs.count - maxWaypoints)). getGoogleDirectionsRoute; must be in-band (min/max from minMaxAcceptableMinutes).

Gemini Routes added via free-engine path get lazy Gemini naming: after append, if isTemplateRouteName(name, description) (e.g. “10 min walk” / “A short walk from start and back.”), a Task calls generateRouteContent and updates the entry in allRoutes and generatedRoute when done.

➕ +1 button (user-triggered)

handleGenerateAdditionalRoute() runs when the user taps +1. Guard: !varietyExhausted, additionalRoutesGenerated < maxAdditionalRoutes (1), has user location, has API key. Then isGeneratingAdditionalRoute = true, additionalRoutesGenerated += 1.

Pre-gen yields to +1: while isGeneratingAdditionalRoute, loop sleeps 2 s and rechecks. Uniqueness via isRouteTrulyUnique(places, distanceMeters) (signature + primary POI). Acceptance via isRouteInWideBand (65–125% for ≤10 min, else 80–120%).

Second-chance: one more tryAddSecondRouteViaFreeEngines; then tryGooglePlacesFallbackToAddRoute with waypointOffset 2, 3. secondChanceTimeCap = 15 s.

🪣 Cross-bucket pool

  • Out-of-band routes (and some short ones) are stored in a session cross-bucket pool keyed by rounded duration.
  • When taking fallback candidates: only routes with duration in 50–150% of selected duration are considered; then sorted so in-band (80–120%) come first, then by closeness to target.
  • Last resort: if no cross-bucket candidates, the best rejected short route is added only if its duration is ≥ 30% of selected.

🚫 Minimum display (30%) & “No routes found”

  • Minimum display % = 30%. A route is shown only if durationMinutes ≥ max(1, selectedDuration × 0.30).
  • If the first route (live) is below 30%: we do not add it. We set allRoutes = [], generatedRoute = nil, showMapPreview = true, errorMessage = "No routes found for X min. Try A, B, C min instead." (other duration options).
  • UI shows title “No routes found” and one button “Choose another duration” (dismisses to duration picker).
📱 App: Error state – “No routes found” / “No routes found for 25 min. Try 10, 15, 20, 30 min instead.” with “Choose another duration”.

📍 POIs & synthetic waypoints

  • Short routes (e.g. 10 min) often get a single turn-around point; if no real POI is within the corridor, the waypoint was named “Scenic North/East/South/West Walk” (synthetic).
  • Fix: For synthetic waypoints we take the GPS of the turn-around point, find the nearest real POI to it, re-measure the route to that POI and back; if the new duration is in-band (50–180% of target), we replace the synthetic waypoint with that real POI (name + route geometry). Applied in mapKitOutAndBack (when we have POIs but none in corridor) and in Tier 2 post-process for “Scenic X Walk” routes.

✨ Gemini naming

  • In-band routes get Gemini name/description via generateRouteContent (waypoints, duration, distance).
  • Routes that are added with a template name (“X min walk”, “A short walk from start and back.”) get lazy Gemini: a Task runs after the route is in allRoutes and updates that entry (and generatedRoute if it’s the current one). Used for: cross-bucket fallbacks, last-resort short route, and initial free-engine second route.
